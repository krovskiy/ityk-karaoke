# ITYK Karaoke

## Code checks

GitHub Actions runs on pushes, pull requests, manual runs, and every Monday.
It checks lint issues, TypeScript, the production build, and production dependencies.
High or critical dependency vulnerabilities fail the audit.

Run the same checks locally:

```sh
npm run check
npm run audit
```

The build does not need .env, a host password, or an Apple API connection.
After pushing the workflow, select "Lint and build" and "Dependency audit" as required
checks in the main branch rules if you want GitHub to block merges when they fail.

A small Node.js + Vite + SQLite app. Plain HTML, no CSS or frontend framework.
Requires Node.js 24 or newer.

## Run it

1. Run `npm install`.
2. Copy `.env.example` to `.env`.
3. Set `ADMIN_PASSWORD` to your host password.
4. Set `VITE_PUBLIC_URL` to the address guests will use.
5. Run `npm run dev` and open http://localhost:5173.

For production: `npm run build`, then `npm start`.
Open http://localhost:3000. The SQLite file is created automatically in `data/`.

## Views

- Audience: `/` — see the current singer and queue, submit a name and song, vote.
- Host: `/host.html` — separate password-protected controls, with no link on the audience page.
- Projector: `/?view=projector` — current singer, queue, QR code and final results.

Each click on "next" finishes the current performance and starts the first waiting one.
Closing voting finishes the current performance and closes submissions.
Only finished performances appear in results. Vote totals stay hidden on the server until reveal.

The host can edit names and songs, move waiting singers up or down, start any waiting singer,
skip a performance, return skipped singers to the queue, and delete performances and their votes.
Live vote counts are available only after host login. Controls refresh every three seconds.
Reopening the event hides public results again. Reset requires typing RESET and deletes all
performances and votes. A page refresh logs the host out.

The top three receive 150, 100 and 50 minion points. Equal votes are ordered by queue entry;
the host should resolve ties before handing out prizes. Bonus categories (costume, duet, etc.)
are chosen manually by the hosts.

One vote per browser per performance, remembered with a cookie.
Clearing cookies or using another browser allows another vote.

## Song search

Type a song or artist in "Find a song", then choose a suggestion.
Apple's public iTunes Search API supplies the title, artist credit, album and artwork.
No API key is needed. This is iTunes catalog search, not the authenticated Apple Music API.
The selected details are saved in SQLite and shown to the host and for the current singer.
Changing the title manually clears the selected details. Manual entry still works if search fails.
The host changing a song title also clears its old metadata.

MUSIC_COUNTRY in .env selects the catalog country (EE by default).
Search waits until typing stops and caches results for five minutes.
Apple documents approximately 20 search requests per minute; this is intended for a small event.
Catalog results do not guarantee Apple Music Sing support or provide playback.
Documentation: https://performance-partners.apple.com/search-api

## Files

- `server/index.ts`: starts Express, connects routes, serves the frontend.
- `server/database/`: SQLite connection, schema updates, and SQL queries.
- `server/logic/`: queue rules, voting rules, host actions, and input validation.
- `server/api/`: Apple search requests and the search cache.
- `server/routes/`: public, music, and host HTTP endpoints.
- `client/index.html`: audience page content.
- `client/src/main.ts`: buttons, API calls, automatic refresh and QR code.
- `client/host.html` and `client/src/host.ts`: host page and controls.
- `config/`: Vite and TypeScript configuration.
- `tsconfig.json`: a small pointer so VS Code discovers the TypeScript configuration.

Edit the TypeScript source files. Files in `dist/` are generated by `npm run build`
and are overwritten on the next build.

Vite serves only the client folder in development. Express serves only dist/client
in production. Server source, environment files, and database files stay outside
the frontend root. Unknown production paths return 404.

For Wi-Fi testing, use your computer's LAN IP in VITE_PUBLIC_URL, not localhost.
Restart development after changing .env; rebuild production after changing VITE_PUBLIC_URL.
For a public event, run behind HTTPS. Hosting at /karaoke-ituk/ needs a reverse proxy that
strips that prefix before forwarding requests. Use a trailing slash: /karaoke-ituk/.
Use a new DATABASE_PATH for a fresh event; restarting keeps the queue and votes.
